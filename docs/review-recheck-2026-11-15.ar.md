# متابعة تنفيذ تقرير مراجعة العمارة — ١٥ نوفمبر ٢٠٢٦

## اختبرت إيه وإزاي؟

راجعت بنود التقرير الأصلي العشرين مقابل المصدر الحالي، وأعدت تشغيل واجهات التطبيق الفعلية في Chromium باستخدام Playwright وبيانات وخدمات محاكاة. اختبارات المدير على عروض ٣٦٠ و٣٩٠ و١٢٨٠ بكسل، وحساب الساكن على ٣٩٠. اختبارات الدليل على ٣٩٠×٦٤٠ و١٢٨٠×٩٠٠، وتشمل جولة البداية والإعادة اليدوية وكل أقسام الشرح التفصيلي.

اختبارات المتصفح تفحص الحفظ المعلق، والفشل والاحتفاظ بالحقول وإعادة المحاولة، وتغير حالة الصيانة والحجز، والرجوع، ونوافذ السداد والحذف، والتقارير ومعاينة الطباعة. اختبار الدليل يفحص ظهور الأهداف وعدم تغطيتها، وإغلاق النماذج دون حفظ، وعدم إرسال عمليات فعلية، وحماية الحقول التي كتبها المستخدم.

شغلت فحص TypeScript وبناء الإنتاج وعشرة اختبارات Node لعميل Neon وتحديثات التطبيق والحسابات والخادم. هذه الجولة لا تشمل تجربة هاتف Android فعلي، أو بريد Google، أو الدفع بالمتجر، أو إشعارات حقيقية. ولم أعد تنفيذ عمليات مالية على قاعدة الإنتاج. اختبارات SQL المعزولة المذكورة في سجل الإصلاحات تخص التنفيذ السابق؛ ليست دليلًا جديدًا من هذه المتابعة.

## النقص الذي كشفته المتابعة

كان اختصار الدليل مطبقًا في التشغيل التلقائي فقط، بينما الإعادة اليدوية تفتح ٤١ خطوة للمدير و٢٢ للساكن. كذلك بقيت نصوص اعتماد ومراجعة حسابات في التقارير ومعاينة الطباعة، ووصف المستشار في اختيار المساعد. لذلك كان إعلان اكتمال هذين البندين سابقًا أوسع من التنفيذ الفعلي.

صُحح المسار اليدوي ليبدأ بخمس خطوات للمدير وأربع للساكن. الشرح التفصيلي اختياري حسب القسم، وينتهي بانتهاء القسم المختار. وصُححت نصوص التقرير والمعاينة والختم ووصف المساعد، وأزيلت أسماء التقنية من قارئ الفواتير وبطاقة المساعد، وادعاء «متصل» الذي لم يكن يعتمد على فحص اتصال.

## مطابقة البنود العشرين

| البند الأصلي | نتيجة المطابقة ودليلها |
| --- | --- |
| ١. بيانات فاتورة مختلقة | الإصلاح موجود؛ فشل قراءة الصورة يحافظ على العنوان والمبلغ، ولا يوجد زر النموذج التجريبي. اختبار متصفح. |
| ٢. تحويل المتأخرات إلى مقدم بعد التسوية | الإصلاح موجود؛ اختبار السداد يحافظ على أساس الأشهر الثلاثة ولا ينشئ رصيدًا مقدمًا وهميًا. مراجعة مسارات الإنشاء والتعديل والحذف. |
| ٣. كتابة مالية جزئية | مسارات Neon تستخدم المعاملة المركزية `mutate_financial_entry`. اختبارات الطلبات المحلية ومراجعة الكود؛ اختبار المعاملة والصلاحيات الفعلي على فرع Neon معزول موثق سابقًا. |
| ٤. إخفاء عجز الخزينة | المعاملة تحفظ الرصيد السالب وتعكس الحركة بقيمتها الحقيقية. مراجعة SQL واختباره المعزول السابق؛ لم يُنشأ عجز تجريبي في الإنتاج. |
| ٥. اختلاف حجوزات المدير والساكن | التحميل والحفظ على السجل المشترك؛ تغيير حالة الحجز وملاحظته ينجح في اختبار الواجهة. |
| ٦. دورة الصيانة الناقصة | تغيير الحالة وإضافة ملاحظة محفوظان؛ اختبار واجهة المدير. |
| ٧. إغلاق نموذج المصروف مبكرًا | انتظار الحفظ، تعطيل الإرسال، الاحتفاظ بالحقول عند الفشل، وإعادة استخدام معرف المحاولة؛ اختبار متصفح. |
| ٨. سجل تدقيق محلي | مسار Neon يقرأ سجل الخادم وتكتب المعاملة سجل الحركة. مراجعة المصدر؛ صلاحيات SQL سبق التحقق منها على Neon. لا تُعامل السجلات المحلية القديمة كسجل خادم موثق. |
| ٩. فشل تحميل الساكن يبدو فارغًا | حقن فشل تحميل السداد والصيانة والحجوزات، ثم إعادة المحاولة؛ تظهر رسالة فشل بدل «لا توجد طلبات». |
| ١٠. المقدم يرفع النسبة | النسبة تستخدم تسوية المستحقات بدل إجمالي النقد؛ مراجعة الحسابات واختبارات Node. |
| ١١. تاريخ ونصوص تجريبية | اختبارات الواجهة تؤكد غياب أكتوبر ٢٠٢٤ وعبارة التجربة من شاشة المدير. |
| ١٢. رجوع الساكن | اختبار انتقال الحساب المالي ثم الصيانة ثم رجوع المتصفح إلى الحساب المالي. زر Android الفعلي لم يُختبر. |
| ١٣. اختصار التحصيل | يفتح نموذج السداد مباشرة؛ اختبار متصفح. |
| ١٤. إجراءات حذف وتعديل ضيقة | إجراءات الشقة النادرة ضمن الخيارات؛ تأكيد الحذف منفصل ومتمركز. اختبارات نوافذ الموبايل والكمبيوتر؛ أضيف اسم واضح ومساحة لمس ٤٤ بكسل لزر إغلاق معاينة الكشف في هذه المتابعة. |
| ١٥. طول بطاقات الشقق | القائمة تستخدم الصفوف المختصرة مع التفاصيل عند الطلب؛ اختبار وجود ١٤ صفًا وعدم الخروج الأفقي. البحث والفلاتر محفوظان. |
| ١٦. تكرار المزيد والإعدادات | القائمة مجمعة حسب المهمة، وإدارة الحساب في إعدادات التطبيق؛ مراجعة المصدر واختبار مجموعة الحسابات والتقارير. |
| ١٧. ادعاء اعتماد ونصوص مضللة | كان غير مكتمل؛ استُكملت نصوص التقارير ومعاينة الكشف والختم والمساعد في هذه المتابعة. اختبارات التقرير والمعاينة تتحقق من غياب ادعاء الاعتماد التلقائي. |
| ١٨. تصنيف أخرى | يظهر في التقرير، والتصنيفات غير المعروفة تُجمع تحته؛ مراجعة الكود واختبار الواجهة. |
| ١٩. خدمات فارغة ولغة واحدة | حالة فارغة واحدة وزر إضافة فني، واللغة معلومة داخل الإعدادات؛ اختبار الدليل الفارغ ومراجعة الإعدادات. |
| ٢٠. طول جولة التعريف | كان غير مكتمل في الإعادة اليدوية؛ أُصلح ليصبح ٥/٤ خطوات، وشرح القسم منفصلًا عند الطلب، مع اختبارات لجميع خطواته الأصلية دون تحويلها لجولة واحدة طويلة. |

هذه متابعة تنفيذ البنود المحددة، وليست ضمانًا بأن التطبيق خالٍ من كل مشكلة محتملة. التقرير الأصلي يبقى سجل الملاحظات وقت المراجعة؛ وهذه الوثيقة هي سجل المطابقة اللاحق.
